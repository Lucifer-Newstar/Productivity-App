## Frozen runtime scope

- Only `get_today@1.0` is registered.
- READ / ANALYZE / SUGGEST only.
- The only evidence envelope is `core.today@1.0`; its bounded existing attention projection does not authorize a separate Notifications route.
- Health consent remains false and no Health payload enters the snapshot.
- Notes, habits content, AI memory and retrieval are not exposed.
- Context/model/runtime settings remain configurable and provisional.
- Deterministic mock proves integration, not model quality.

## Adversarial interpretation

Injection-like text may be displayed verbatim as a user-authored task/notification label; displaying data is not executing it. The security requirement is that such text cannot change policy, request unregistered tools, add permissions, cite unknown IDs or claim mutation. v0.1 tests all those boundaries.

## Live integration acceptance

On 2026-08-19, the actual engine and frontend development entry points were started together. A manual HTTP/SSE smoke through the fixed Next.js proxy proved pairing, unsupported-intent rejection, fixed route creation, exact `get_today@1.0` arguments, synthetic snapshot submission, deterministic response/source/freshness verification, session revocation and clean process shutdown. Home returned HTTP 200. Visual browser automation was not used; fixed-purpose UI and browser revision checks remain covered by frontend QA and production build.

**Decision:** PASS — v0.1.1 is accepted as the deterministic/mock baseline.
